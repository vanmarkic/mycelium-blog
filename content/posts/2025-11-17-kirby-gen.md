## Introduction

Kirby-Gen is an ambitious AI-powered portfolio generator that transforms the traditionally complex process of building custom CMS sites into a conversational experience guided by Claude.

## The Story

### Context: What I Was Building

Creating a professional portfolio shouldn't require weeks of configuration and technical expertise. Kirby-Gen bridges this gap by using AI to automate the entire process—from initial domain mapping conversations to one-click deployments.

The system uses **Claude Opus** for intelligent domain modeling conversations, extracting design tokens from visual inspiration sources, and automatically generating Kirby-compatible content structures and blueprints. Users describe what they want through natural conversation, and the AI translates those requirements into fully functional Kirby CMS sites.

The architecture is a **monorepo** containing:
- **React 18 frontend** with TanStack Query and Zustand for state management
- **Express.js + Socket.IO backend** for real-time AI interactions
- **FastAPI Python skills server** for AI-powered features
- **Kirby 4 site generator** for CMS deployment

### The Challenge

**Bridging conversational AI and structured CMS output** is fundamentally difficult. Claude understands intent, but Kirby needs precise blueprints, content types, and structured data. The challenge: translate free-form conversations into the rigid structures Kirby expects—without losing the user's creative vision.

**Design token extraction from inspiration** requires visual understanding. Users provide references—screenshots, existing sites, color palettes—and the system must extract consistent design tokens (typography scales, color systems, spacing) that work cohesively.

**One-click deployment** with regeneration support means managing state across multiple regenerations. Users refine their vision iteratively. The system must track what changed, preserve user content, and update only what's necessary—not wipe everything and start over.

### How I Solved It

**AI-driven domain mapping** starts conversations about the portfolio's purpose, target audience, and content structure. Claude doesn't just collect requirements—it asks clarifying questions, identifies gaps, and suggests content organization strategies.

**Intelligent blueprint generation** translates domain models into Kirby blueprints programmatically. The system maintains templates for common portfolio patterns (project showcases, blog posts, case studies) and adapts them based on conversation context.

**Design system editing in Kirby** makes the generated design tokens editable directly in the Kirby admin panel. Users can refine colors, typography, and spacing without touching code.

**Test-Driven Development (TDD)** across all packages ensures reliability. Comprehensive unit, integration, and E2E tests prevent regressions when iterating on AI prompts or generator logic.

**MIT License** ensures maximum accessibility for the open-source community.

### What I Learned

**Conversational AI needs structured output layers.** Claude's strength is understanding nuance, but production systems need predictable data structures. The solution: maintain strict TypeScript interfaces between conversational AI and code generation layers.

**Visual design extraction isn't magic.** Extracting cohesive design tokens from inspiration requires careful prompting and validation. Users might provide a screenshot with beautiful colors but inconsistent spacing. The system must balance extraction accuracy with design coherence.

**Regeneration is a feature, not a bug.** Users don't get portfolios right the first time. Supporting iterative refinement through regeneration—without losing work—is harder than initial generation but infinitely more valuable.

**TDD prevents AI-induced chaos.** When your code generator is driven by AI conversations, comprehensive tests are essential. Prompt tweaks can cascade unpredictably. Tests catch breaking changes before users do.
